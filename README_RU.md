# TupoNVR

**Намеренно простой NVR для RTSP-камер на вашем сервере.**

[English](README.md) · [Документация](docs/README_RU.md)

Смотрите IP-камеры в прямом эфире, записывайте видео и находите нужный момент на общей шкале архива. Для дома, небольших систем видеонаблюдения и домашних лабораторий: один контейнер приложения и один контейнер MediaMTX; запись не зависит от открытого браузера. [Начните работу](#быстрый-старт) с Docker Compose.

[<img src="docs/images/archive-synchronized.png" alt="Синхронизированный архив TupoNVR" height="360">](docs/images/archive-synchronized.png)

*Скриншот браузерного теста с синтетическим видео; у четвёртой камеры пропуск. Нажмите для увеличения.*

Настройки камер можно первоначально загрузить, сохранить и импортировать через YAML на странице камер; изменения проверяются до подтверждения. См. [конфигурацию камер](docs/camera-configuration_RU.md).

## Возможности

- Управление RTSP-камерами с отдельными статусами доступности и записи.
- Прямой эфир отдельной камеры и сохранённый мультиэкран с перемещением и изменением размеров плиток; дополнительные потоки камер.
- Запись только видео в MP4 без перекодирования, недельные расписания, срок хранения и защита подключённых хранилищ по идентификатору.
- Общая шкала архива нескольких камер, скачивание, экспорт периода и сохранение кадров в PNG.
- Интерфейс на английском и русском, часовой пояс установки, необязательный общий вход, вебхуки, endpoints состояния и метрик.

## Быстрый старт

Нужны **Linux, Docker Engine, Docker Compose 2.24.4+**, сетевой доступ к RTSP-камерам и доступное для записи хранилище со свободным местом сверх стандартного резерва **5 GiB**. Используйте современный браузер с WebRTC и MP4; начните с H.264. Python, Node и FFmpeg на хосте не нужны.

1. Скачайте конфигурацию установки (curl или браузер; исходники не нужны):

   ```sh
   mkdir -p TupoNVR
   cd TupoNVR
   for file in docker-compose.yml compose.lan.yml mediamtx.yml .env.example; do
     curl -fL "https://raw.githubusercontent.com/vvbelousov/TupoNVR/dev/$file" -o "$file"
   done
   cp .env.example .env
   ```

2. Измените `.env`: задайте `NVR_IMAGE=vvbelousov/tuponvr:0.2.1`, `NVR_BIND=0.0.0.0`, обе переменные `AUTH_USERNAME` и `AUTH_PASSWORD`, оставьте `WEBRTC_HOST` пустым. Локальные записи хранятся в `./recordings`; внешнее хранилище сначала смонтируйте. Разрешите доверенным зрителям **TCP 8080 и UDP 8189**; TCP-порты хоста **8554, 8889, 9997** должны быть свободны.

3. Загрузите образ Docker Hub с фиксированной версией и запустите:

   ```sh
   docker compose -f docker-compose.yml -f compose.lan.yml pull
   docker compose -f docker-compose.yml -f compose.lan.yml up -d --no-build
   ```

4. Откройте **`http://<host-address>:8080`** и войдите. Задайте часовой пояс в **Аккаунт → Предпочтения**. В **Камерах** добавьте основной RTSP URL и учётные данные камеры, нажмите **Проверить**, убедитесь в статусе **Пишет** в **Обзоре**. Камеры и запись по умолчанию включены и работают при готовом хранилище. **Смотреть** открывает прямой эфир; для архива нужен завершённый сегмент (обычно около 10 минут или ближайшая граница часа) и индексирование, которое может занять ещё пять минут.

Этот вариант для Linux LAN использует сеть хоста; TCP-службы MediaMTX слушают loopback. **Вход в приложение не защищает прямой доступ к MediaMTX**: держите эти endpoints закрытыми и доверяйте локальным процессам хоста. В последующих командах используйте те же Compose-файлы. [Установка](docs/installation_RU.md) описывает localhost/bridge-режим, [безопасность](docs/security-hardening_RU.md) — HTTPS и доступ через VPN.

## Философия проекта

TupoNVR следует философии Unix и принципу KISS: проверенные инструменты, узкая задача и система, которую можно понять и обслуживать самостоятельно. Простота намеренная. Практические улучшения просмотра и поиска записей соответствуют проекту; распределённая корпоративная инфраструктура видеонаблюдения выходит за его рамки.

## Известные ограничения

- Нет аудиозаписи, детекции, PTZ, обнаружения и управления через ONVIF, пользовательских ролей и нативного мобильного приложения.
- Воспроизведение зависит от поддержки кодека браузером; поддержка H.265 различается. Статус камеры Online не гарантирует воспроизведение.
- Синхронизация архива практическая, без покадровой точности. Заявленных тестов производительности или числа камер нет.
- Отключение питания может оставить незавершённые MP4; автоматического ремонта и резервного копирования нет. Монтирование и восстановление NAS — задачи хоста.
- Один общий аккаунт, нет ограничения перебора пароля; используйте доверенную LAN или VPN и HTTPS для удалённого доступа. Прямые endpoints MediaMTX обходят вход.
- Не опубликованы проверенный список моделей камер, результаты нативного запуска на ARM и длительных испытаний реальных камер/NAS. См. [совместимость и диагностику](docs/troubleshooting_RU.md).
