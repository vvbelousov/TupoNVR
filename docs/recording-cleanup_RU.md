# Ручная очистка записей

[Документация](README_RU.md) · [English](recording-cleanup.md)

В Хранилище доступно **Управление записями / Очистка хранилища**. Выберите все камеры или несколько, всё время или местный диапазон даты/времени. Примените фильтры для обновления списка. Время использует пояс установки из Аккаунта независимо от браузера. Отсутствующее время DST отклоняется; повторённое требует выбора раннего/позднего варианта.

Предпросмотр охватывает все отфильтрованные записи или выбранные ID. По 100 строк на странице; Выбрать всё выделяет только текущую страницу. Выбор сохраняется между страницами, сбрасывается при смене фильтров. Предпросмотр показывает число, индексированные размеры, камеры, период и активные исключения, не меняет файлы/индекс. Размеры из SQLite; освобождённые байты измеряются при удалении и могут отличаться из-за отсутствия/изменения файла.

Нужен диалог подтверждения. Для всех камер за всё время дополнительно введите `DELETE`. Целые сегменты пересекают `[start, end)`: `segment.start < end && segment.end > start`. Поэтому вместе с сегментом удаляется и видео за пределами выбранного периода. Обрезки/перекодирования нет. Фильтры камер, диапазона и ID пересекаются.

## Архитектура и API

Записи — UTC MP4 по пути `recording-root/destination/camera-id/YYYY/MM/DD/HH/YYYYMMDDTHHMMSS.mp4`. Таблица SQLite `segments` — единственный индекс; FFprobe наполняет её после закрытия сегментов. Список, шкала и синхронизированный просмотр используют её; удалённые строки исчезают из будущего поиска. Завершение очистки через лёгкое storage event обновляет вкладки архива того же браузера, останавливая устаревший выбор воспроизведения. Существующий просмотр сообщает о недоступных файлах без сбоя. Используется существующая аутентификация:

- `POST /api/recordings/cleanup/query?offset=0&limit=100`: страницы метаданных и общее число; принимает `camera_ids`, `recording_ids`, `start`, `end`.
- `POST /api/recordings/cleanup/preview`: те же пересекающиеся критерии, предпросмотр и непрозрачный token на 15 минут.
- `POST /api/recordings/cleanup/delete`: `{token, confirmation}`; для очистки всего `DELETE`, иначе `confirm`; возвращает 202 и token задачи.
- `GET /api/recordings/cleanup/progress/{token}`: processed/total, deleted, реально освобождённые байты, активные исключения, отсутствующие файлы/ID и ошибки.
- `DELETE /api/recordings/{id}` использует то же защищённое удаление; активный файл — 409, небезопасное/недоступное хранилище или ошибка unlink — 503.

Пути, размеры и числа удаления от клиента не принимаются. API-границы требуют UTC offsets. Диапазон очистки не ограничен 31-дневным окном воспроизведения архива.

## Защита и согласованность

Выполнение использует фиксированный снимок предпросмотра, повторно проверяя строки под archive lock. Новые/заменённые строки не расширяют подтверждённую операцию. Исключения предпросмотра остаются исключёнными после закрытия. Повторный token возвращает ту же задачу без нового удаления. Ручная и автоматическая очистка разделяют lock и helper.

Выходной каталог FFmpeg зарегистрирован до создания процесса и защищён до завершения остановки. Весь каталог консервативно исключён, включая закрытые сегменты рядом с активным; очистка не останавливает камеры. Регистрация ждёт в worker thread, обслуживание архива не блокирует ASGI event loop.

Удаление открывает корень и каждый компонент пути с `O_NOFOLLOW`, проверяет настроенный `.nvr-storage-id` через открытое назначение и идентичность каталога, удаляет только индексированный обычный MP4 с известным путём recorder и ID камеры. Пропавшие/несовпадающие защищённые mounts безопасно отклоняются. Незащищённые локальные назначения сохраняют прежнее поведение; внешним задайте storage ID. Каталоги, неизвестные файлы, markers, база и конфигурация не удаляются. Небезопасные строки и повреждённые неиндексированные файлы остаются для проверки.

После успешного unlink SQLite коммитится отдельно для каждого файла. При ошибке unlink строка сохраняется. Отсутствующие файлы в проверенном назначении убирают устаревшие строки, освобождают ноль байт и отдельно сообщаются. Отсутствие назначения не оправдывает удаление метаданных. Файловая система и SQLite не атомарны: crash/ошибка базы после unlink оставляет строку для следующей очистки. Неудалённый файл не показывается успешно удалённым. Если обновление индекса не удалось после unlink, освобождённые байты учитываются, строка остаётся для согласования. Сроки хранения не меняются.

## Ограничения

Прогресс и снимки в памяти процесса: до 32 сохранённых предпросмотров/задач. Завершённые задачи и неиспользованные previews истекают через 15 минут; работающие продолжаются. Лёгкий daemon thread удаляет файлы, UI опрашивает прогресс. Перезапуск теряет прогресс и прерывает задачу; новый preview согласует отсутствующие строки. Требуется один процесс, несколько ASGI workers не поддерживаются. Уход со страницы прекращает polling, не отменяет удаление. Новый сервис, очередь и база не нужны.

Выбираются только индексированные записи; ещё неиндексированное видео недоступно. Активные каталоги консервативно исключены. Дополнительного выделения на общей шкале просмотра, возрастных presets и встроенной кнопки удаления в Archive нет.
