## Редактирование камер

Редактор получает сохранённые поля через защищённый `GET /api/cameras/{id}/edit`: полный путь URL без userinfo, имя пользователя, дополнительный поток и прочие настройки. Пароли не возвращаются; поле пароля пустое. Query options скрыты, поскольку могут содержать токены производителя; если новый URL не содержит query, сохраняются прежние options. Новая query полностью заменяет старую.

Встроенные учётные данные сохраняются при изменении безопасного URL без смены username/password. Новый пароль заменяет старый, пустой сохраняет его. Новое имя пользователя сохраняет пароль; пустое убирает userinfo URL. Обзор и общие списки показывают сокращённые URL.

Форма отправляет только изменённые поля через `PATCH /api/cameras/{id}`. Пропущенные поля сохраняются; `substream_url:null` явно убирает дополнительный поток. `PUT` тоже поддерживает частичную правку и прежнее поведение пустых URL/пароля и `clear_substream`. API создания не изменён. Ошибки проверки не возвращают исходный запрос с паролем/токеном.

## Недельные расписания

В редакторе включите **Ограничить часы записи**, настройте пояс установки в **Аккаунте**, задайте 1–14 окон с днями и временем. Без расписания запись непрерывная. `enabled` и `recording_enabled` — главные переключатели: расписание не включает отключённую камеру и не ограничивает прямой эфир.

Пример `recording_schedule` при создании/правке:

```json
{"timezone":"Europe/Moscow","windows":[{"days":[0,1,2,3,4],"start":"22:00","end":"06:00"}]}
```

Поле `timezone` сохранено для старых клиентов; все окна фактически используют пояс установки. Дни 0–6 — понедельник–воскресенье, относятся к дню начала окна. Конец раньше начала означает переход через полночь, включая воскресенье→понедельник. Начало включительно, конец исключительно. Полный день — `00:00`→`24:00`; равные времена запрещены.

DST использует местное время: осенний повторённый час случается дважды, весенний отсутствующий пропускается. Граница применяется на следующей синхронизации (обычно до пяти секунд), затем FFmpeg имеет до 15 секунд на завершение. Файлы остаются в архиве. `null` убирает расписание; пропуск поля при правке старым клиентом сохраняет его.

## Общие вебхуки

Задайте `WEBHOOK_URL` (HTTP(S)) и необязательный `WEBHOOK_TOKEN`, пересоздайте контейнер приложения. Интеграций отдельных провайдеров и дополнительных сервисов нет. Сбой ожидаемой записи/хранилища должен длиться `WEBHOOK_DEBOUNCE_SECONDS`; непрерывный сбой даёт одно событие. Восстановление даёт `recovery`; выключение записи или выход из расписания закрывает инцидент как `resolved`. Новые инциденты соблюдают `WEBHOOK_COOLDOWN_SECONDS`. Сбой общего назначения создаёт событие хранилища и подавляет дубликаты событий камер.

Пример JSON POST:

```json
{"id":"stable-event-uuid","kind":"recording","camera_id":1,"destination":"nas","reason":"stalled","state":"failure","occurred_at":"2026-10-06T09:00:00+00:00"}
```

События хранилища не включают `camera_id`. Нет имён камер, приватных URL, паролей, путей и raw errors. `X-NVR-Event-ID` повторяет `id`; token добавляет `Authorization: Bearer ...`. Endpoint и token не показываются в UI/логах. Вне доверенной LAN используйте HTTPS. Redirects не выполняются, proxy environment игнорируется.

Очередь и debounce сохраняются в SQLite. Отдельная coroutine не блокирует запись: timeout пять секунд, до трёх попыток с задержками 10/20 секунд. Только успешные HTTP-ответы считаются доставкой. Порядок FIFO; окончательно неудачные доставки не блокируют recovery навсегда. Получатель должен убирать дубликаты по `id`: перезапуск может повторить POST.

Очередь содержит до 1000 ожидающих событий; завершённые/неудачные удаляются через семь дней. Статус виден в **Хранилище** и `/api/notifications/status`. Новый URL перенаправляет очередь туда; пустой URL приостанавливает доставку и наблюдение. Это уведомления при работающем NVR, не о полном отключении сервера и не постоянный журнал инцидентов.

## Язык интерфейса

Поддерживаются английский и русский; стандартный язык английский независимо от языка браузера. Задайте `DEFAULT_LANGUAGE=en` или `DEFAULT_LANGUAGE=ru` в `.env`, пересоздайте контейнер согласно [установке](installation_RU.md#управление-запуском). Другие значения дают понятную ошибку запуска.

Выбор **Языка** — в **Аккаунт → Предпочтения** (`/account`), внизу бокового меню (на мобильном рядом с названием). Изменение сразу действует и сохраняется в local storage, приоритетнее сервера. Login использует сохранённый выбор или серверный язык. Даты используют выбранный язык и пояс установки. При отключённом browser storage выбор действует до конца визита; следующий использует серверный язык. Удаление ключа `nvr-language` возвращает серверное значение.

`GET /api/language` без входа возвращает только `{"default_language":"en"}` (или `ru`) для login. Обычные API конфигурации/камер/хранилища сохраняют требования входа.

## Ограничения

Нет аудиозаписи, детекции, PTZ, ONVIF, нескольких пользователей, фонового перекодирования и нативного мобильного приложения. API не вычисляет FPS/bitrate; читает `bytes_received` MediaMTX без декодирования. Повреждённые отключением питания MP4 не ремонтируются. Резервируйте SQLite, сохранённые настройки и записи отдельно.

Сигнализация браузера требует входа при его настройке; прямые TCP-службы MediaMTX должны оставаться закрытыми. Очистка по сроку ограничивает рост базы/записей, но неограниченное хранение требует внешнего мониторинга места. Синхронизация архива без покадровой точности: начала записей с точностью секунды, задержка камер, кодек, сеть и декодеры браузера ограничивают точность и большой выбор камер.
