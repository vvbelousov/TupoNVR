# Время установки, запись и синхронизированный архив

[Документация](README_RU.md) · [English](time-and-archive.md)

## Метки времени и модель данных

- SQLite `segments.started_at` / `ended_at` — TEXT с UTC ISO 8601 и offset (`+00:00`). Recorder/indexer нормализуют UTC; запросы приводят вход с offset к тому же представлению. Локальная интерпретация SQLite не используется.
- FFmpeg работает с `TZ=UTC`, имена используют календарь UTC и точность секунды; время медиа сбрасывается в каждом сегменте. Индекс получает начало из имени, конец — прибавлением длительности ffprobe. Пояс установки не меняет имена/записи.
- Прогресс, проверки, JSON logs, retention, `occurred_at` вебхуков и доставка остаются UTC. Время прогресса/последнего файла Обзора и доставки Хранилища отображается в поясе установки.
- Раньше Archive использовал даты UTC, фиксированную 24-часовую шкалу и фильтр по дате начала сегмента. Поиск времени уже принимал абсолютные метки; previous/next пропускал перекрытия, сообщал gaps. Браузер форматировал UTC, но создавал расписания в своём поясе.
- Абсолютные начало/конец и относительный seek файла достаточны для практической синхронизации. Точность начала имени — секунда, без покадрового timecode.

## Настройка часового пояса

Псевдонимы нормализуются через link metadata серверной базы поясов (например, US/Eastern → America/New_York). У установки один IANA-пояс для всех пользователей, браузеров и расписаний. `APP_TIMEZONE=UTC` инициализирует только установку без сохранённого выбора; сохранённый UI-пояс приоритетнее.

**Аккаунт → Предпочтения → Изменить часовой пояс** даёт searchable native datalist серверных зон, выбранную зону и текущее местное серверное время. Сохранение сразу меняет ожидания расписаний. Другие клиенты получают его с опросом конфигурации, обычно до десяти секунд.

`settings.json` лежит рядом с `DATABASE_PATH`, обычно `/data/settings.json` на существующем volume. Запись использует приватный временный файл, fsync файла/каталога, atomic rename и lock процесса. Нет новых таблиц, колонок, индексов, миграции, зависимостей или инфраструктуры. `SETTINGS_PATH` может изменить путь для прямого запуска. Резервируйте файл вместе с данными; ручная правка требует restart. Неверная конфигурация вызывает ошибку запуска, а не незаметную смену времени записи.

**Обновление:** прежние `recording_schedule.timezone` хранятся и принимаются API для совместимости, но не переопределяют пояс отдельно. До использования старых расписаний задайте пояс установки. Все окна используют его местное время. Смена может запустить/остановить запись, но не меняет метки видео. Редактор показывает действующий пояс.

Расписания сохраняют включительное начало, исключительный конец, дни начала окна, переход через ночь и воскресенье→понедельник, `00:00`→`24:00` для полного дня. Python `zoneinfo` учитывает offsets: осенний повторённый час доступен дважды, весеннего отсутствующего нет. Вычислений с постоянным offset не добавлено.

## Границы местного дня

Браузер форматирует абсолютное время через `Intl` и настроенный пояс независимо от своего. Сервер разрешает местный ввод через `zoneinfo`. День может занимать 23/24/25 или дробное число часов; шкала использует реальную длительность UTC. Включены пересекающие день сегменты, даже начавшиеся другой датой.

Для повторённого времени resolver возвращает оба абсолютных варианта с offsets; пользователь выбирает до воспроизведения. Отсутствующее время/пропущенная дата дают понятную ошибку без автоматического сдвига. Старый `date=` API сохраняет UTC-семантику для совместимости; UI использует явные `start`/`end`.

## Просмотр архива и устройство воспроизведения

По умолчанию Archive предлагает **Выбрать камеры…**; прямые live-ссылки выбирают свою камеру. Выберите одну, несколько через раскрывающийся список или все; **Выбрать все** / **Очистить** меняют только временное состояние исследования. Выберите местные дату/время или нажмите/перетащите общую шкалу, включите просмотр. Дорожки показывают доступность/пропуски. Drag делает локальный preview и один lookup после отпускания; стрелки (пять минут на полном дне, одна на коротком диапазоне)/Home/End выбирают preview, Enter/Space запускает seek.

Состояние истории отдельно от Multiview и сохранённого layout. Адаптивная сетка раскладывает камеры и складывается на узком экране. Отдельная камера входит в fullscreen с теми же media elements и общей сессией.

Общие логические часы привязывают абсолютное UTC к `performance.now()`. Offsets равны `(master UTC time − segment UTC start)`. Начало ждёт metadata доступных файлов до пяти секунд, чтобы медленная камера не блокировала всех. Затем buffering, ошибка поиска, отсутствующий файл, кодек или gap влияют только на свою камеру. Часы не зависят от одного видео.

Контроллер каждые 250 мс применяет общие play/pause/rate, исправляет дрейф только сверх **750 мс** или при явном seek/resume/rate. Ждёт metadata, не мешает текущему seek, не повторяет pending native play promises. Часы обновляются по целым секундам. 0.5×/1×/2×/4× — native playback без перекодирования/композиции.

В конце сегмента batch lookup находит файл для текущего времени с offset перекрытия. При gap кэшируется начало следующего сегмента; камера подключается по достижении без polling внутри gap. Переходы независимы. Lookup timeout десять секунд, устаревшие запросы отменяются при смене сессии. Ошибка повторяется через пять секунд только для своей камеры. Отсутствие будущего видео не создаёт повторных запросов; **Обновить** или новый seek обнаруживают свежий индекс.

Доступны single-camera previous/next, download, страницы, automatic-next. При отключённом automatic-next одна камера останавливается на границе. Общий просмотр останавливается, когда у всех выбранных камер исчерпан индекс. Fullscreen сохраняет часы. Язык меняется в Аккаунте; уход из Archive завершает просмотр согласно обычной навигации.

## API времени и архива

Все endpoints используют существующую аутентификацию:

- `GET /api/config`: `timezone`, UTC `now` и прежняя конфигурация WebRTC.
- `GET /api/time`: `timezone`, UTC `now`, допустимые `timezones`.
- `PUT /api/time`: `{ "timezone": "Europe/Moscow" }`, сохраняет и согласует расписания.
- `GET /api/time/day?date=2026-10-06`: UTC `start`, `end` дня установки и местные ticks с offsets.
- `POST /api/time/resolve`: `{ "date": "2026-10-06", "time": "14:32:17" }`; `instants` с UTC `time` и местным `local` с offset.
- `GET /api/recordings`: `start`, `end`, `camera_ids` через запятую; пересекающие сегменты, прежние limit/offset.
- `POST /api/recordings/timelines`: `{ "camera_ids": [1,2], "start": "...Z", "end": "...Z" }`; объединённые intervals/gaps по камере, один запрос диапазона, максимум 31 день/20 000 сегментов; при превышении сократите диапазон.
- `POST /api/recordings/resolve`: `{ "camera_ids": [1,2], "time": "...Z" }`; текущий сегмент, seek seconds и следующий по камере. Один HTTP и SQL с индексированным поиском camera/time. Отсутствующие камеры/записи дают пустой выбор, не ошибку всего запроса.

Прежние single-camera timeline/at/adjacent/file API совместимы. Метаданные не содержат путей/паролей. Абсолютное время без offset запрещено. Существующие MP4 отдаются с byte ranges. Single-camera timeline ограничен 5000 сегментами; список UI загружает по 200 с **Загрузить ещё**.

## Ограничения и проверки

Браузер и хост требуют актуальные базы поясов. Часы камеры/recorder и секундное индексирование ограничивают точность; коррекция 750 мс касается дрейфа браузера, не гарантирует время съёмки. Кодек/seek, сеть и декодеры ограничивают большие наборы камер; каждая потребляет отдельные ресурсы. Logs/webhooks намеренно UTC.

Тесты покрывают UTC/Москву/DST и дробные дни, повторённое/отсутствующее время, ночные окна, неизменность SQLite schema/меток видео, atomic configuration, auth, local overlap, batch offsets/gaps, API validation. Clock tests покрывают offsets, pause/resume/rate, drift, границы, rejected play promises. Chromium с реальными API/SQLite/native videos и другим поясом браузера проверяет возврат после gap, независимые переходы, shared seeks, fullscreen, выбор, DST, responsive layouts на обоих языках.

## Экспорт периода и сохранение кадров

Действия Multiview/Archive находятся в строке имени камеры. Archive: snapshot, fullscreen, download, single-camera previous/next. Multiview: Archive, fit/fill, snapshot, fullscreen, основной поток, удаление. Controls переносятся на узких плитках и доступны в fullscreen.

**Архив** live-player и **Недавние записи** отдельной камеры открывают перезагружаемую `/archive?camera=…&at=…Z` ссылку на пять минут раньше серверного времени с выбранной камерой и шкалой 15 минут. **5/15/30/60 min** показывают окно до курсора (до серверного времени перед просмотром); **Полный день** возвращает местный день установки. Смена диапазона сохраняет камеры, players, позицию, скорость и play/pause. Диапазоны могут пересекать полночь/DST, запросы UTC; тёмные дорожки — gaps.

**Экспорт клипов** расположен под шкалой суточных записей и изначально свёрнут. Открытие и закрытие сохраняют воспроизведение, интервал и камеры. Верхняя часть шкалы сохраняет курсор перехода; янтарная полоса выбирает интервал перетаскиванием, отдельные границы задают начало и конец. Дорожки камер продолжают работать для перехода. Границы поддерживают стрелки (секунда), Shift+стрелки (минута), Home и End. Ручные поля и границы синхронизируются абсолютными моментами времени. Масштаб и дата не меняют интервал; кнопки показа начала/конца открывают пятиминутное окно без перехода воспроизведения.

Независимые флажки позволяют выбрать одну, несколько или все камеры. Одна камера даёт MP4; несколько — ZIP с отдельным MP4 каждой успешной камеры и `manifest.json`. Выбор камер по умолчанию следует за камерами архива до первого ручного изменения экспортных камер. Поля используют часовой пояс установки; повторяющееся местное время раскрывает выбор раннего/позднего вхождения, несуществующее отклоняется. Смена часового пояса меняет отображение разрешённых границ, сохраняя абсолютные моменты; неразрешённые ручные значения сбрасываются. Начало включительно, конец исключительно в пределах точности кадров источника.

- **Точные границы (кодирование)** обрезает частичные сегменты FFmpeg и кодирует H.264 исходного размера (libx264 CRF 18 в production; libopenh264 8 Mb/s при отсутствии libx264). Это кодирование с потерями. Полные сегменты автоматически копируются. Если части кодируются, кодируются все выбранные части для совместимого объединения.
- **Исходное качество (по ключевым кадрам)** копирует без перекодирования; seek/cuts могут включать видео за пределами или отличаться на GOP. Когда границы важны, используйте exact. Кодек зависит от браузера.
- Gaps, включая начало/конец, пропускаются без искусственных кадров; UI показывает абсолютные интервалы в местном поясе. Видео склеивается без ожидания gaps. Перекрытия обрезаются без намеренного дублирования времени. Только видео, как в записях.
- Индексированные отсутствующие/удалённые/недоступные файлы дают ошибку выбора; внешнее удаление при обработке, повреждение, непригодные clips и несовместимая смена кодека/размеров дают ошибку задачи. Такие файлы не пропускаются с показом полного результата. Полностью удалённый период без индекса даёт 404. При смене разрешения сократите период; exact допускает смену исходного кодека, если кодированные части совместимы.

Защищённый API принимает время с offset, нормализованное UTC:

- `POST /api/recordings/exports`: `{ "camera_id": 1, "start": "2026-10-06T11:32:00Z", "end": "2026-10-06T11:37:00Z", "mode": "exact" }` (`copy` также допустим); 202 со случайным token, `state`, `completed`, `total`, `gaps`, `error`, эффективным `mode`. Вместо `camera_id` можно передать `camera_ids: [1, 2]` (1–64 различных положительных ID настроенных камер или индексированных архивов удалённых камер); оба поля одновременно запрещены.
- `GET /api/recordings/exports/{token}`: прогресс по сегментам, `processing`, `ready`, `failed`, `downloading`. Дополнительные поля: `phase` (`preparing`, `processing`, `packaging`, `ready`, `failed`), `format` (`mp4`, `zip`), `partial`, `cameras` с состояниями, счётчиками, пропусками, эффективным режимом, именем файла и ошибкой каждой камеры. Проценты не оцениваются.
- `GET /api/recordings/exports/{token}/download`: MP4 для одной запрошенной камеры, ZIP для нескольких (даже если успешна лишь одна), скачивание потребляет результат. Не готов/повторная загрузка — 409; истёкший/использованный token — 404.

Задачи — ограниченные threads backend, до двух работающих и 16 сохранённых. Предел 31 день и 2000 сегментов. FFmpeg: 15 минут на команду, час на задачу, два encoding threads. Данные/диагностика на диске, не в памяти Python. Временный `exports` рядом с базой резервирует запас для частей, результата и ZIP всех задач. Недостаток места отклоняется с 507; сократите период. Лимит временных данных на задачу — 8 GiB; проверка свободного места во время FFmpeg требует минимум 256 MiB. Ошибки диска/хранилища дают failed. Прогресс после каждой части; затем сборка и decode validation до ready. Большая часть может долго не менять счётчик. Copy тоже декодирует результат для проверки без кодирования.

Камеры обрабатываются последовательно одним существующим FFmpeg-конвейером с общим часовым сроком. Сбой камеры не мешает другим, если продолжение безопасно. Если нет успешных камер, задача завершается ошибкой. Частичный результат явно помечен `partial`; manifest содержит UTC-интервал, запрошенный режим и исход каждой камеры, эффективный режим и известные пропуски. Имена файлов используют числовые ID и не содержат путей. ZIP64 формируется потоково с диска без сжатия MP4. Лимит 2000 сегментов общий для всех камер. Используется действующая общая авторизация установки; отдельной модели прав камер нет. Интерактивная отмена экспорта не предусмотрена; остановка backend прекращает активные задачи.

Выбор и pinning разделяют `video.ARCHIVE_LOCK` с автоматической/ручной очисткой. Pins reference-counted; guarded deletion пропускает их как активные. Lock отпускается до FFmpeg, другое видео можно чистить. Pins снимаются при успехе/сбое/timeout/штатной остановке. Текущие файлы записи запрещены для экспорта. После готовности независимого результата оригиналы можно удалять обычным образом. Неудачные intermediates удаляются сразу; ready/failed истекают через час после обработки; завершение/разрыв скачивания удаляет результат. Штатная остановка прекращает export FFmpeg и удаляет jobs; startup очищает оставшиеся после crash каталоги. Один worker, без новой службы, схемы базы или зависимости.

**Сохранить кадр** делает PNG текущего decoded live/archive frame в исходном размере через canvas браузера. Просмотр/fullscreen сохраняются. Без decoded media, canvas или при ограничениях security/codec показывается сообщение; backend не может восстановить точный отображённый кадр без декодирования браузером — повторите после начала просмотра. Временные object URLs освобождаются.

Retrieval tests декодируют реальные exports: один/несколько сегментов, copy preservation, overlaps/gaps, отсутствующие/удалённые/повреждённые файлы, неверные ranges/без offset, гонки очистки, shutdown/restart, offsets через полночь и DST. Browser tests проверяют live/archive PNG, live navigation с сохранением камеры, ranges без сброса просмотра, timeline boundaries, export/download, gaps, frame feedback, оба языка и мобильную ширину.
