# Конфигурация камер через YAML

[English](camera-configuration.md) · [Документация](README_RU.md)

Доступно с **0.2.1**. SQLite остаётся основным хранилищем. YAML используется для первоначальной настройки, явного импорта/экспорта и переноса настроек; синхронизации при перезапуске нет. Глобальные настройки остаются переменными окружения. Видео, метаданные записей, раскладки, защита хранилищ/маркеры и часовой пояс установки в экспорт не входят.

## Схема версии 1

См. [пример](examples/cameras.yaml). Верхний уровень: `version: 1` и список `cameras` (до 500 камер). Неизвестные поля/версии, повторяющиеся ключи, пользовательские теги, псевдонимы YAML, файлы не в UTF-8 и документы больше 1 МиБ отклоняются. Пустой список допустим, пустой файл — нет. Глубина вложенности и сложность документа также ограничены; большие импорты с множеством расписаний разбивайте на несколько файлов.

| Поле камеры | Значение / по умолчанию для новой камеры |
|---|---|
| `key` | Обязательный стабильный ключ: 1–64 латинских буквы, цифры, `_` или `-` |
| `name` | Обязательное название, 1–100 символов |
| `rtsp_url` | Обязательный URL с `rtsp://` или `rtsps://` |
| `username`, `password` | Необязательные учётные данные; отсутствие/null/пустая строка сохраняют существующие |
| `enabled` | Логическое значение, `true` |
| `recording_enabled` | Логическое значение, `true` |
| `recording_destination` | Каталог на томе записи, `default`; 1–64 латинских буквы/цифры/`_`/`-` |
| `retention_days` | Целое число 1–3650, по умолчанию 7; `null` — без ограничения |
| `substream_url` | Необязательный RTSP URL, `null` |
| `description` | Текст до 1000 символов, по умолчанию пустой |
| `recording_schedule` | Расписание; `null` — непрерывная запись |

Расписание содержит `windows` (1–14 окон) с уникальными целыми `days` (понедельник=0, воскресенье=6), `start` и `end` в формате `HH:MM`. Только `end` допускает `24:00`. Ночное окно продолжается на следующий день. Поле совместимости `timezone` сохраняется, но **запись использует часовой пояс установки из «Аккаунта»**; импорт камер его не меняет. Если timezone отсутствует, используется часовой пояс установки. Строки учётных данных/URL не допускают управляющих символов и ограничены 4096 символами.

## Идентификация и совместимость

При запуске миграция присваивает существующим камерам стабильные случайные ключи. ID SQLite и связь с записями сохраняются. Ключи не меняются при экспорте или переименовании. Импорт сопоставляет камеры **только по ключу**: новый ключ создаёт новую камеру, даже если название или URL совпадают. Для редактирования установки начните с экспорта; при переименовании не меняйте ключ.

Неуказанные поля существующей камеры сохраняются. Null в retention/schedule снимает ограничение; null substream удаляет дополнительный поток; пустые URL сохраняют прежние. Удаление учётных данных через YAML не поддерживается. Импорт создаёт/обновляет/сохраняет без изменений и не удаляет отсутствующие камеры. Повторный импорт идентичной конфигурации идемпотентен.

## Необязательная первоначальная настройка в Docker Compose

Подготовьте `cameras.yaml`, скачайте `compose.bootstrap.yml` рядом с файлами установки и добавьте его к обычной команде Compose. Пример для готового образа `vvbelousov/tuponvr:0.2.1` после публикации:

```sh
curl -fsSLO https://raw.githubusercontent.com/vvbelousov/TupoNVR/dev/compose.bootstrap.yml
docker compose -f docker-compose.yml -f compose.bootstrap.yml up -d
```

Сохраняйте все прежние overlays (например `compose.lan.yml`) в последующих командах. При необходимости задайте `CAMERA_BOOTSTRAP_FILE=/absolute/path/cameras.yaml` в `.env`. Overlay монтирует существующий файл только для чтения в `/config/bootstrap/cameras.yaml`, не создавая отсутствующий путь на хосте. Без bootstrap используется обычная команда и дополнительные каталоги не нужны. При запуске без Docker файл можно поместить по тому же фиксированному пути приложения.

Если файла нет, приложение запускается обычно. При наличии хотя бы одной камеры bootstrap пропускается. В пустую базу корректный файл импортируется целиком в транзакции до активации камер. Некорректный YAML, ошибка чтения или базы вызывают предупреждение без секретов, а **запуск продолжается**, чтобы исправить настройки через UI. При ошибке проверки база не меняется. Перезапуск не перезаписывает изменения UI. Если удалить все камеры и оставить файл, следующий запуск импортирует его снова; отключите overlay/файл, чтобы избежать этого.

## Экспорт, резервная копия и импорт

Откройте **Камеры → Импорт / Экспорт → Экспорт YAML**. По умолчанию исключены пароли, логины, встроенные учётные данные URL и параметры запроса URL, которые могут содержать токены. Хосты и пути сохраняются. Для переноса авторизованных камер явно выберите **Включить учётные данные**; интерфейс предупредит о секретах в файле. Ответ экспорта содержит `Cache-Control: no-store`. Ограничивайте права/шифруйте резервные копии и не сохраняйте их в репозитории.

Для переноса экспортируйте с учётными данными, отдельно подготовьте каталоги записи и часовой пояс целевой установки, выберите файл на странице камер, затем **Предпросмотр изменений → Подтвердить импорт**. Экспорт без секретов пригоден для редактирования и переноса анонимных камер; при необходимости добавьте учётные данные локально. Новая камера с логином без пароля отклоняется. Для анонимных новых камер выводится напоминание о возможной необходимости учётных данных. Отсутствующий/пустой пароль не очищает существующий. При импорте URL без секретов сохраняются прежние встроенные учётные данные и параметры запроса.

Предпросмотр показывает создание/обновление/камеры без изменений, изменения полей, ошибки, конфликты ключей и предупреждения. Изменения подключения и учётных данных обозначаются без значений. Выбор файла не применяет импорт. Подтверждение сохраняет всё одной транзакцией SQLite. Изменение настроек или документа делает предпросмотр устаревшим (409); требуется новый предпросмотр. Перезапуск сервера также аннулирует предпросмотры. После успеха список камер обновляется.

Активация камер и обновление MediaMTX выполняются после сохранения. При ошибке UI сообщает о сохранённых настройках и отложенной активации; обычная периодическая сверка повторит попытку. SQLite не может откатить внешние процессы. YAML сохраняет только настройки камер; для полного восстановления нужны обычные резервные копии базы и видео. Экспорт без секретов не восстанавливает отсутствующие пароли/токены; защита хранилищ настраивается отдельно.

## API

Все маршруты используют существующую авторизацию (публичны только при отключённой авторизации приложения).

- `GET /api/camera-config/export`: скачивание `cameras.yaml`; `include_credentials=true` явно включает секреты.
- `POST /api/camera-config/preview`: тело — UTF-8 YAML (`Content-Type: application/yaml`), до 1 МиБ. Возвращает `create`, `update`, `unchanged`, `errors`, `conflicts`, `warnings`; `fingerprint` есть только при успешной проверке. Ошибки проверки возвращаются в предпросмотре с HTTP 200; превышение размера — 413.
- `POST /api/camera-config/apply`: то же тело YAML, заголовки `X-Confirm-Import: true` и `X-Import-Fingerprint: <fingerprint>`. Ответ: счётчики `created`, `updated`, `unchanged` и `runtime_pending`. Нет подтверждения/неверная конфигурация — 422; устаревший предпросмотр — 409; ошибка базы с откатом — 503.

Ответы не кэшируются. Предпросмотр не сохраняет секреты на сервере; fingerprint — временный хеш с ключом, учитывающий документ, камеры и часовой пояс установки. ID базы никогда не используются как переносимые идентификаторы YAML.
